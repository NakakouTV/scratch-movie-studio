アニメーション操作API

Base URL: http://127.0.0.1:8601/api。エージェントは含まれません。HTTPから公式エディタを操作できます。命令の戻り値は編集完了後に返ります。

独立カット

独立カット画面では、準備を録画せずに実行し、必要な操作だけを撮影できます。POST /cuts に projectId, title, start: "project" / "blank", setup: [], actions: [], framing: {target, block, scale}, endFraming, beforeMs, afterMs, speed を指定します。構図は任意、余白は0〜30000msです。進捗は GET /jobs/{id}、撮り直しは POST /cuts/{id}/retake に {} または変更する項目を渡します。元動画は残し、新しいカットを生成します。元sb3との完成一致検証や途中再開は行いません。実行・マウス操作も収録できます。開始時の素材は読み込み済みです。範囲選択用の制作手順は GET /projects/{id}/cut-plan で取得します。

sb3から動画を作る

// JavaScript / Node.js 18+
const project = await fetch(base + '/projects', {
  method: 'POST',
  headers: {'Content-Type': 'application/octet-stream'},
  body: sb3Bytes
}).then(r => r.json());

const job = await fetch(base + '/jobs', {
  method: 'POST', headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({projectId: project.id, speed: 1, demoSeconds: 3})
}).then(r => r.json());
// GET /jobs/{id} で進捗と成果物URLを取得

標準では背景・コスチューム・音の追加も録画します。素材を準備済みにする場合は animateAssets: false をジョブに指定します。

自動生成する手順では、入力欄へ別のブロックを入れる場合、隠れる数値・文字・色の定数を元sb3の値へ書き換えず、パレットの初期値を保ちます。実際に使う定数や、他の選択肢に影響する対象メニュー等は設定します。完成比較は有効な接続と値を比較するため、隠れた既定値の違いで失敗にはしません。この省略は新しく生成する手順に適用されます。保存済みの手順や、明示的な block.input 命令は引き続きその入力を実行します。

場面別の動画出力

ジョブ作成時の outputMode に full（全体のみ・APIの初期値）、scenes（場面別のみ）、both（両方）を指定します。管理画面の初期値は「全体＋場面別」です。MP4生成を無効にした場合、動画は出力しません。

自動手順の plan.scenes は、対象ごとの素材追加、変数・リスト、定義作成、各スクリプトの組み立てに分かれます。定義は呼び出しより先に作成するため、「定義の作成」と「定義の中の処理」は別の場面です。完成後の実演は demoSeconds > 0 のとき最後の場面になります。

POST /jobs
{
  "projectId": "読み込んだID",
  "outputMode": "both",
  "demoSeconds": 3,
  "scenes": [
    {"title": "素材の準備", "from": 1, "to": 10, "enabled": false},
    {"title": "プログラムを作る", "from": 11, "to": 31, "enabled": true}
  ]
}

scenes を省略すると自動分割を使います。指定する場合、from / to は1始まり・両端を含む操作番号で、1操作目から最後までを重複・隙間なく指定します（上の例は31操作の手順用）。名前は200文字以内。最大1000場面です。enabled: false はその場面の個別MP4だけを省略します。後続に必要な変数・素材・定義をそろえるため、すべての制作操作を順に実行し、全体動画には全操作を収録します。

完成後の成果物には scenes/001.mp4 などの連番動画と scenes.json（名前、操作範囲、出力ファイル、録画区間、概算秒数）が追加されます。秒数は結合前の収録時間合計で、MP4のフレーム・音声の丸めによりわずかに異なります。場面名はファイル名に使わないため、同じ名前も指定できます。

途中保存・再開では録画区間と場面の対応も復元します。場面境界でドラッグや入力を終えて保存するため、直接の mouse.* / keyboard.* / project.* を含む独自手順は場面別出力の対象外です。実演には demoSeconds を使ってください。出力設定は制作開始時に固定されます。

途中保存と再開

自動生成した制作手順は25操作ごと、対象切替時、素材追加後に保存します。保存済みsb3・ID対応表・元の素材・録画区間・履歴は outputs/{id}/ に残り、サーバー再起動後も再開できます。

POST /jobs/{id}/pause   // 現在の操作を完了し、保存して一時停止
POST /jobs/{id}/resume  // 最後に保存された操作の次から再開
GET  /jobs             // 保存済みの制作履歴
GET  /jobs/{id}         // checkpoint.step / resumable / status

ジョブ作成時の checkpointEvery は1〜100（初期値25）。再開時は元の設定を引き継ぎます。失敗や中止からも保存地点に戻って再開でき、未保存区間は撮り直します。失敗原因が残っていれば同じ操作で再び停止します。録画区間は完成時に結合し、失敗途中の映像は完成動画に含めません。

直接の mouse.* / keyboard.* / project.* 操作を含む独自手順と個別操作セッションは途中再開の対象外です。実行中の変数・スレッドやドラッグ途中の状態は保存しません。通常の完成後の実演は自動再構築を保存した後に行います。旧版で作成したジョブは保存地点がないため再開できません。

読みやすい倍率

ジョブ・セッション作成時に minScale: 0.8（初期値）を指定できます。範囲は0.3〜1.5。画面に収まらない移動は、倍率を下げずにブロックをつかんだままコード領域をスクロールして行います。カーソルとブロックのつかみ位置を同期し、途中でマウスを離しません。遠距離では移動時間を延ばします。セッション中は {"type":"view.configure","minScale":1} で変更できます。

workspace.zoom は全体像を見せるため指定倍率に一時的に変更します。次のブロック操作時には下限以上に戻ります。明示的な縮小を維持したい場合は view.configure で下限も変更してください。

1操作ずつ動かす

POST /sessions
{"projectId":"読み込んだID","blank":true}

POST /sessions/{id}/actions
[
  {"type":"target.select","target":"Sprite1"},
  {"type":"block.add","sourceId":"flag","opcode":"event_whenflagclicked",
   "place":{"x":80,"y":80}},
  {"type":"block.add","sourceId":"move","opcode":"motion_movesteps",
   "place":{"after":"flag"}},
  {"type":"block.input","block":"move","input":"STEPS","value":"123"}
]

sourceIdは呼び出し側が決める別名です。以後そのIDでブロックを指定できます。別名はスプライトごとに管理します。配置座標はコード領域のワークスペース座標です。

block.add はパレット内の現在位置を使い、対象がつかめる位置にあればスクロールもカテゴリのクリックも行いません。近い場所（おおむねパレット1画面分以内）や同じカテゴリ内はスクロールだけで移動し、遠い別カテゴリに限ってカテゴリをクリックします。明示的な category.select は指定どおりクリックします。

block.add / block.move の place.after、または place.parent と place.input を指定すると、その接続先だけにスナップします。型が合わなければエラーになります。place.x / y の場合は近くのブロックに自動接続せず配置します。制御は各APIドラッグの終了・失敗時に解除され、通常のマウス操作には残りません。

構造と元のブロックID

GET /projects/{id}/structure は読み込み元のsb3を返す参照APIです。version: 1、idScope: "target"、extensions、targets を返します。編集中の状態は下記の状態APIから取得してください。

各対象には name / isStage / selectAction、スクリプトの入口 scripts、全ブロック blocks、定義と呼び出しの関係 procedures、variables / lists / broadcasts / costumes / sounds が含まれます。ブロックには元の id / opcode / category / parent / next / fields / inputs / mutation が含まれます。入力値は kind: block / literal / reference で区別し、上書きされて隠れた既定値も fallback に保持します。変数参照はID・所有対象・global/localを区別します。

const structure = await fetch(base + `/projects/${project.id}/structure`).then(r => r.json());
const target = structure.targets.find(t => !t.isStage && t.scripts.length);
// POST /sessions/{id}/actions に送る例（そのブロックが既に存在する場合）
const actions = [target.selectAction,
  {type: 'workspace.focus', block: target.scripts[0].rootBlockId}];

IDは対象ごとの範囲です。対象を選択してから操作してください。同じsb3から空の状態に再構築する場合も、block.add.sourceId 等にこのIDを使います。入力内の短縮形式の変数・リストは 親ID::入力名（synthetic: true）で、標準制作手順と共通です。定数などのshadowは親の block.input / block.field と入力名で編集してください。別作品や外部で編集し直したsb3までIDの一致を保証するものではありません。

現在の状態と操作結果

GET /sessions/{id}/state（従来の GET /sessions/{id} も同じ内容）は、画面を動かさずに現在の状態を返します。

selectedTarget / selectedTab対象名・isStage、code / costumes / sounds
workspacescale、scrollX、scrollY、dragging
modal / fieldEditorOpen表示中のダイアログのtype・label（なければnull）、入力欄やドロップダウンが開いているか
running / busy / recordingScratch実行中、API編集操作中、録画フレーム収集中。MP4変換中はrecordingがfalseになります。
currentAction / lastAction実行中の命令／最後に完了した命令。sequence、action、startedAt。lastActionにはcompletedAt、successとresultまたはerror。まだなければnull。
blocks選択対象のブロック。内部id、対応するsourceId・sourceIds、parent・nextとそれぞれのSourceId、fields、inputs。inputsのsourceNameは定義呼び出しの元引数ID、sourceBlockIdは接続先の元ID。

元のsb3から読み込んだブロック、またはAPIで別名を指定して作ったブロックに元IDを対応付けます。画面で手作業により追加したブロックなど、対応がない場合は sourceId: null です。ダイアログのlabelも取得できない場合はnullになります。複数操作の途中で失敗すると後続は実行せず、失敗した命令をlastActionに残します。部分的に画面が変わっている可能性があるため、状態を確認してから続行してください。状態取得はタブ切替やフォーカス移動を行わず、操作中に取得した状態は途中の状態です。

素材の追加

セッション作成時に blank: true, animateAssets: true を指定すると、透明な準備用コスチューム1枚から開始します。読み込んだsb3を素材元として保持し、最初の画像追加後に準備用コスチュームを画面上で削除します。スプライトを選び、{"type":"costume.add","assetIndex":0} または {"type":"sound.add","assetIndex":0} を実行します。OSのファイル選択画面は収録せず、ファイルは自動選択します。

特殊な設定欄

block.input と block.field は同じ入力判定を使います。色は #rrggbb を指定すると色選択画面のスライダーを操作し、元のRGB値を保持します。角度・数値・文字は入力エディタ、キー・対象・素材・ペンの色特性などは選択メニューで設定します。入力後の値も確認します。

メッセージ名

実際に使う送信・受信ブロックを置き、その block.field に field: "BROADCAST_OPTION", value: "開始" を指定します。送信ブロックには input: "BROADCAST_INPUT" も指定します。存在しない名前は公式ダイアログで作成します。

「対象の属性」ブロック

sensing_of は、先に block.field で input: "OBJECT", field: "OBJECT", value: "対象スプライト名" を選び、その後 field: "PROPERTY", value: "x position" 等を設定します。ステージにはx座標・y座標の選択肢がありません。内部値と現在の画面の日本語表示の両方で指定できます。自動制作手順ではこの設定順序を適用し、旧手順の隣接したPROPERTY→OBJECTの順序も未実行部分で補正します。

配置の指定

{"place":{"x":100,"y":200}}                       // 独立したブロック
{"place":{"after":"flag"}}                      // 下につなぐ
{"place":{"parent":"loop","input":"SUBSTACK"}} // 繰り返しの中
{"place":{"parent":"move","input":"STEPS"}}    // 入力に計算ブロックを入れる

初期版の範囲

ブロックの編集、変数・リスト・定義ダイアログ、PENを対象にしています。背景・コスチューム・音は公式アップロードメニューから追加できます。スプライト属性・変数の初期値はデータから準備します。ペイント・音声の詳細編集、クラウド同期、ハードウェア拡張は未対応です。未対応の入力形式はエラーとして停止し、成功扱いにはしません。録画にはScratchの実行音を含みます。

同じセッションの操作は順番に呼び出してください。/jobsで生成した操作列はplan.jsonに保存され、編集したplanを次のジョブのplanに指定できます。失敗時は操作ログと画面画像を保存します。
