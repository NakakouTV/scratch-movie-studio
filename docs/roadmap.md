# 解説動画素材ツールの追加機能案

2026-09-25。途中保存・再開、倍率下限制御、場面別の動画出力は実装済み。以下には今後の拡張案も含む。AIエージェント・ナレーション生成は本ツールに含めず、外部から操作できるAPIと素材の出力を中心にする。

## 1. 途中保存と再開（最優先）

長い作品では、コスチューム1枚の選択に失敗しても全体を最初から撮り直す負担が大きい。まず「失敗原因を修正した後に、安全な保存地点から再開する」方式を追加する。

- 25〜50操作ごと、スプライト切替時、素材追加完了時にチェックポイントを保存する。
- 編集中sb3に加え、完了した操作番号、操作手順、元の素材、編集中の対象、ブロック別名、変数・メッセージ・定義引数のID対応表、エディタの版を保存する。sb3だけでは、残りのAPI操作が指すIDを復元できない。
- 保存直後の入力欄・メニューを閉じた安定状態から再開する。失敗した追加操作の結果がすでに存在する場合もあるので、無条件に同じ操作を再送しない。
- 録画はチェックポイント単位の区間に分ける。再開時には正常に完了した区間を残し、撮り直した区間を結合する。位置が飛ぶ場合は場面の切れ目として扱う。
- サーバー再起動後もジョブ履歴と再開地点を読めるようにする。

最初の受入条件: 数百操作の途中で故意に失敗させ、アプリ再起動後に再開して、ブロックや素材を重複させず元の作品との比較に合格すること。

## 2. 読める倍率を保つ表示制御（優先度: 高）

現在の配置制御は、確実に操作できることを優先している。大きな計算式では最小倍率まで縮小されるため、解説素材として文字を読むには小さすぎる場面がある。

- 制作向けの倍率下限を指定できるようにする。初期候補は0.7〜0.8だが、実際の1080p動画で読めるかを確認して決める。
- 全体を一画面に収めるより、説明対象のブロック・入力欄を読みやすい倍率で表示する。
- 遠い場所へは現在の中継ドラッグを利用し、マウスを離した後にスクロールする。
- 全体像を見せる場面だけ明示的に引く。ステージの実行結果を見せる場面ではステージ表示を広げる。
- APIには対象、希望倍率、移動時間、表示後の待ち時間を指定できるようにする。

最初の受入条件: 横に長い3Dの式でも、操作対象の文字が読める倍率を維持し、画面外でドロップしないこと。

## 3. 場面指定と部分制作（優先度: 高）

実装済み: 対象・素材・変数・定義・スクリプトごとの自動分割、場面名の編集と出力対象選択、APIによる操作範囲指定、全体／場面別／両方のMP4出力、場面一覧JSON、途中保存・再開。依存関係を保つため制作操作は全体を順に実行する。開始状態を直接準備して制作時間を省く機能や、場面順の組み替えは今後の拡張。

sb3の配置順と、説明しやすい順番は一致しない。「定義を作る」「繰り返しの中を追加する」「完成例を実行する」を場面として指定できるようにする。

- スプライト、スクリプト、定義、操作範囲を指定して、必要な部分だけ撮影する。
- その場面の前提となる変数・定義・素材を明示する。準備済みにするか、作成過程を撮るかを選べるようにする。
- 「完成例 → 最小構成 → 機能追加 → 実行確認」のような順番を操作手順で表現する。
- 各場面を別MP4として出力し、連続動画としての出力も選べるようにする。

## 4. 待機・強調・編集用の時刻情報（優先度: 中）

- 入力直後や実行結果の表示後に、説明に必要な時間だけ静止する。
- 指定ブロックや変数を一時的に囲むなど、任意の強調をAPIで付けられるようにする。通常は公式Scratch画面のままにする。
- 場面と各操作の開始・終了時刻をJSONに出し、外部ツールがナレーションや字幕を合わせられるようにする。
- フレーム番号も出力し、録画の時刻と対応させる。実時間の操作ログだけで編集位置を推定させない。

## 次に実装する範囲の提案

途中保存・再開、倍率制御、場面別出力を実装済み。次は場面単位の待機時間や編集用の正確な時刻情報を検討する。自動的な説明文の生成や読み上げは、これらのAPI・時刻情報を利用する別の仕組みに任せる。
