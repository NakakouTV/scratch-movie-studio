# 盤面クリック・リスト操作・条件待機

独立カットの`setup/actions`、または個別セッションの操作APIで使用します。ゲームのルールを作る機能ではなく、既存のScratch作品で実演映像を撮るための操作です。通常の自動再構築ジョブには指定できません。

独立カット画面の「盤面クリックの実演」から設定のひな形を作れます。対象スプライトとリストは読み込んだ作品から選びます。初期値は8×8・1マス24px・左下のクリックで、成功時にリストが「黒マス」へ変わる想定です。実際に石を置ける行・列と作品の配置に合わせ、JSONを編集して撮影してください。ゲーム開始と準備の待機は録画外です。

## 盤面

```json
{"type":"board.configure","rows":8,"columns":8,"cellWidth":24,"cellHeight":24,"target":"マス"}
{"type":"board.click","row":4,"column":3}
```

- 行・列は1始まり。1行目は下、1列目は左です。
- `board.configure`は行・列数（1〜100）、マスの幅・高さ（0より大きく480以下）、任意の`left,bottom,target`を設定します。`left,bottom`は盤面の左端・下端のScratch座標です。省略時は盤面を(0,0)にセンタリングします。
- 設定なしでは8×8・24px・中心配置です。設定はセッション内で維持し、撮り直しではsetupから設定し直します。
- クリックする位置は`x=left+(column−0.5)×cellWidth`、`y=bottom+(row−0.5)×cellHeight`です。編集画面・全画面の実際のステージサイズから画面座標を求めます。
- `target`を指定すると、そのスプライトまたはクローンが最前面でクリックできることを確認します。モニターや別のスプライトが重なる、マスが画面外にある、クローンがまだ表示されていない場合はクリックせずエラーにします。
- マウスを移動した後に再確認して実際にクリックします。ゲーム側のクリック処理は通常どおり実行されます。クリックの戻り値は要求の完了であり、石の配置成功ではありません。必要な結果を`runtime.wait`で確認します。
- `board.click`の`holdMs`は押して離すまでの時間です。既定80ms、0〜1000ms。マウスが押された状態を調べるスクリプトにも入力が届くよう、短い押下時間を設けます。

## リスト

```json
{"type":"list.set","scope":"global","name":"マスの状態","values":["空マス","白マス","黒マス"]}
{"type":"list.replace","scope":"global","name":"マスの状態","index":2,"value":"黒マス"}
{"type":"list.get","scope":"global","name":"マスの状態"}
{"type":"list.get","scope":"global","name":"マスの状態","index":2}
```

既存リストだけを操作します。全体の設定は`list.set`、1項目の変更は`list.replace`、読み取りは`list.get`です。番号は1始まり。`values`は最大10000項目で、値は文字列または有限の数値です。`list.get`は番号省略時に全体を、番号指定時はその項目を返します。範囲外の読み取り・変更はエラーです。

`scope:global`は全体のリスト。`scope:local`は`target`のオリジナルスプライト（省略時は選択中）のリストです。クローン固有のリストは対象外です。`name`の代わりに`id`を指定でき、制作時のsourceIdにも対応します。同名リストを全体・ローカル間で自動推定しません。

値の変更は実演用のデータ操作であり、入力欄へ一文字ずつ書く動作ではありません。リストの表示は更新しますが、盤面描画は作品のスクリプトが行います。値の変更後に描画処理を実行する必要がある作品では`script.run`等も指定してください。実行中のスクリプトが同じリストを変更すると競合します。

## 条件待機

```json
{
  "type":"runtime.wait",
  "conditions":[
    {"type":"list","scope":"global","name":"マスの状態","index":20,"value":"黒マス"},
    {"type":"variable","scope":"global","name":"進行状況","value":"白のターン"}
  ],
  "mode":"all",
  "timeoutMs":10000,
  "stableMs":100
}
```

条件は1〜100件。`all`（既定）はすべて、`any`は少なくとも1件の条件が成立したら進みます。

| 条件のtype | 確認する値 |
| --- | --- |
| `variable` | 変数の値。scope・target・name/idで識別 |
| `list` | indexを指定した要素。property:lengthなら項目数。どちらも省略するとvalueの配列と全体比較 |
| `cloneCount` | targetで指定したスプライトのクローン数。オリジナルは数えない |
| `running` | モニター用の処理を除くスクリプトが実行中か。valueはtrue/false |

`op`は`equals`（既定）、`notEquals`、`contains`、`gt/gte/lt/lte`。配列とrunningはequals/notEquals、cloneCountはcontains以外です。大小比較は数値に変換して比較します。等価比較ではScratchの実演で混在しやすい数値1と文字列"1"を同じものとして扱います。

変数・リスト要素の条件には、文字列・有限の数値に加えtrue/falseも指定できます。定義の戻り値に入った真偽値を待つ場合に使えます。

待機上限は0〜60000ms（既定10000）、条件の安定時間は0〜5000ms（既定100、上限が100未満なら同じ時間）です。安定時間は上限以下にします。上限0・安定時間0ではその時点の条件を1回確認します。条件が崩れたら安定時間を数え直します。初期化中に指定したリストの項目がまだなければ待機を続けます。

タイムアウトではエラーにし、最後の条件と値をログに残します。存在しないデータ名は即時エラーです。独立カットの中止は待機中も確認するので、長い待機が終わるまで中止ボタンを待つ必要はありません。

変数・リストの条件成立は描画完了を直接証明しません。必要な状態・クローン数を条件に含め、安定時間も指定してください。ずっとループがある作品ではrunning:falseは停止操作まで成立しません。

状態APIの各`targets`には`lists`（id/name/length/values）と`cloneCount`も返ります。状態取得ではマウスを動かしません。

状態APIの`board`には、そのセッションの盤面設定が返ります。

検証: `node tests/board-actions.mjs`。4×4のクローン盤面で、編集・全画面のクリック、全体/ローカルリスト、値の更新、条件待機・タイムアウト、遮蔽、MP4、中止を確認します。
