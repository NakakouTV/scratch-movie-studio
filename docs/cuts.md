# 独立カット

`http://127.0.0.1:8601/cuts.html` でsb3を読み込み、制作手順の開始・終了番号を指定します。「この範囲から設定を作る」で、範囲より前を録画外の準備、範囲内を撮影操作として設定できます。設定JSONは編集できます。元sb3の素材は撮影前から読み込まれています。

## API

`POST /api/cuts` は非同期でジョブを返します。進捗・結果は `GET /api/jobs/{id}`、中止は `POST /api/jobs/{id}/cancel` で取得・指定します。

```json
{
  "projectId": "アップロードしたプロジェクトID",
  "title": "数値を入力するカット",
  "start": "blank",
  "speed": 1,
  "subtitleMargin": 220,
  "setup": [
    {"type": "target.select", "target": "Sprite1"},
    {"type": "block.add", "sourceId": "move", "opcode": "motion_movesteps", "place": {"x": 200, "y": 200}}
  ],
  "framing": {"target": "Sprite1", "block": "move", "scale": 1},
  "beforeMs": 500,
  "actions": [
    {"type": "block.input", "block": "move", "input": "STEPS", "value": "30"}
  ],
  "endFraming": {"block": "move", "scale": 1},
  "afterMs": 1000
}
```

対象名は実際のsb3に合わせて変更してください。`start` は `project`（元sb3を読み込んだ状態、既定値）または `blank`（素材と対象を準備し、コードを空にした状態）。`setup` と `actions` には既存の操作APIを指定します。実行・停止・マウス・キー操作も使用できます。開始と終了の余白は0〜30000ms、速度は0.25〜10です。撮影前の準備も同じ速度で実行しますが動画には含めません。

`subtitleMargin` は画面下の字幕用の余白です。初期値220px、0〜400の整数で指定でき、0で無効にします。操作するブロック・入力欄が余白へ近づくと中央付近へ自動スクロールします。パレットからつかむ位置と構図も余白を避けます。動画のサイズ・Scratch内のブロック座標は維持します。画面からの生成では「字幕用の余白」の選択を使用し、撮り直しでは元カットの設定を引き継ぎます。

`framing` は準備後・録画前、`endFraming` は撮影操作の後・後ろの余白の前に適用します。対象選択、コードタブ、倍率、指定ブロック全体の中央配置を行います。倍率は0.3〜1.5。ブロック全体が入りきらない指定はエラーにします。省略すればその時点の表示を維持します。ブロックIDは対象スプライト内の元ID、または準備時に付けたsourceIdです。操作中のスクロールを禁止する機能ではありません。複数範囲の自動構図、ステージ拡大は今回の対象外です。

カーソルは収録前と撮影操作終了後に右下へ退避します。後ろの余白へ移る際の退避操作も動画に入ります。余白は録画を続ける待機時間であり、動作中のScratchを静止画にする処理ではありません。

`GET /api/projects/{id}/cut-plan` では、素材が準備済みの状態に対応する制作手順を取得できます。独立カット画面の範囲選択はこの手順を使います。

## 撮り直し

`POST /api/cuts/{id}/retake` に `{}` を送ると、保存済みの元sb3・設定から新しいカットを生成します。元動画は上書きしません。ボディに `actions`、`framing`、`title` などを渡すと、その項目全体を置き換えて撮り直します。構図の解除には `null` を指定できます。サーバー再起動後も元のアップロードIDは不要です。

保存場所は `outputs/{id}/` です。`cut.json`（再現用設定）、`source.sb3`（元プロジェクト）、`start.sb3` と `start.jpg`（録画開始直前）、`result.sb3`、`movie.mp4`、`recording.json`、`log.json` を保存します。途中失敗・中止の映像は完成動画として公開しません。

途中からの再開ではなく、準備からの撮り直しです。sb3に実行中のスレッド・ペン描画・乱数状態は保存されないため、開始状態で必要な実演操作もsetupに指定します。毎回新しいブラウザで準備しますが、乱数・外部入力・実時間による結果の違いは残ります。部分制作を許すため、元sb3との完成一致検証は行いません。各編集操作の接続・入力確認は従来どおり行います。

検証: `node tests/cuts.mjs`（Chrome・FFmpeg・ffprobeが必要）。録画外準備、部分編集、構図、MP4、サーバー再起動後の撮り直し、失敗区間の分離、実演操作を検証します。

## 実演用の操作

独立カットのsetup/actions、または個別セッションのactionsで次の操作を使用できます。完成sb3との一致を検証する通常の再構築ジョブには指定できません。

```json
[
  {"type":"variable.set", "scope":"global", "name":"値", "value":0, "duration":1500},
  {"type":"script.run", "target":"Sprite1", "block":"先頭ブロックのsourceId"},
  {"type":"stage.view", "mode":"fullscreen"},
  {"type":"sprite.drag", "target":"Sprite2", "x":80, "y":-30, "duration":1000},
  {"type":"stage.view", "mode":"editor"}
]
```

- `variable.set`：既存の変数へ実行時の値を代入します。`scope: global` は全体変数。`scope: local` は `target` で指定したスプライト（省略時は選択中の対象）の変数です。`name` または `id` で識別し、リストは対象外です。値は有限数値または文字列。`duration` を省略すると即時変更、0〜60000msを指定すると数値を直線的に変化させます。これは入力欄での文字入力アニメーションではなく、値を操作するAPIです。実行中のスクリプトが同じ変数を書き換える場合は競合します。
- `script.run`：指定した対象のスクリプトの先頭ブロックを実際にクリックします。必要に応じて全画面を終了し、対象・コードタブへ移動します。入力内のブロックや途中のブロックは受け付けず、既に実行中なら停止に切り替わらないようエラーにします。戻り値はクリック要求の完了であり、スクリプトの完走を意味しません。必要な待機・停止操作を後続に指定してください。
- `sprite.drag`：名前で指定したオリジナルのスプライトを、Scratch座標の `x/y` へ実際のマウス操作でドラッグします。時間は0〜60000ms、初期値1000ms。透明部分・重なり・モニター等を避けてつかむ位置を探し、最後に座標を確認します。つかめない対象やカーソルの終点がステージ外になる指定はエラーです。クローン指定は未対応です。
- `stage.view`：Scratchの全画面ボタンで `fullscreen` / `editor` を切り替えます。編集画面のドラッグはScratch仕様に従い、座標がドロップ時に更新されます。ドラッグ中も実行結果を更新したい場合は全画面表示を使い、事前にScratchの「ドラッグできる」設定を行ってください。APIが勝手に設定を変えることはありません。

ステージ上での実演の後に `endFraming` を指定すると、編集画面へ戻って指定ブロックを表示します。全画面のままカットを終了したい場合はendFramingを省略してください。

状態API `GET /sessions/{id}/state` の `stageMode` で表示モード、各 `targets` の `x/y/visible/draggable/variables` で座標や変数値を取得できます。変数の `id/name/value` はその対象が所有する値です。

追加検証: `node tests/demo-actions.mjs`（通常サーバー起動が必要）。同名変数の範囲、値の時間変化、ネイティブのブロッククリック、編集画面・全画面のドラッグ、未対応指定、後始末を検証します。`node tests/cuts.mjs` はこれらの実演操作をMP4へ収録する経路も確認します。
